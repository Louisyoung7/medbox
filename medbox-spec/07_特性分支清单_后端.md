# 07 · 特性分支清单（Java 后端）

> 每个 `- [ ]` 待办 **对应一个特性分支**，分支名见每条的 `feat/xxx`。
> **修 Bug、重构项目结构不计入本清单**（不单独开分支记账，随所在模块一起提交即可）。
> 图例：🧱 = **地基（本人完成，后续任务依赖它）**；🔧 = **功能任务（分配给学弟学妹）**。
> 依赖列的分支必须先合并；"参考"指向 `medbox-spec/` 下的文档章节，实现前请先读对应章节。
> 完成后勾选 `- [x]`，并在 PR 描述里写明"对应 07 清单第 N 项"。

> **路径与分支**：本清单所有代码**都在 `medbox-server/` 下**（如 `src/main/resources/application.yml` = `medbox-server/src/main/resources/application.yml`）；分支名 `feat/backend-xxx`，**一个分支只改 `medbox-server/`**。文档改动（`medbox-spec/`）与代码放进**同一个 PR** 即可，**不要求同一个 commit**（按层分批提交也可以）。
>
> **构建工具约定（V1.9 起）**：后端是**单项目 Gradle 工程（Kotlin DSL，Wrapper 9.7.1）+ Spring Boot 4 + JDK 21**（编译与目标运行时均为 21，不再做 `--release 17` 降级）。常用命令：`./gradlew bootRun` 启动、`./gradlew build` 构建、`./gradlew test` 测试；IDE 直接运行 `com.medbox.server.MedboxServerApplication`。**基础包名 `com.medbox.server`**，servlet context-path 为 `/medbox`（故健康检查是 `GET /medbox/actuator/health`）。
>
> **注意 Spring Boot 4 的两个差异**：① 自带 **Jackson 3**（`com.fasterxml.jackson` → Jackson 3 的坐标与 API 有调整，写 DTO / 自定义序列化时留意）；② `spring.ai.*`（Spring AI）需按 Boot 4 对应的 Spring AI 版本引入，`feat/backend-ai-infra` 落地时对齐。
>
> **持久层框架（V1.14 定）**：**MyBatis-Plus**。地基 `feat/backend-db` 只做建表与迁移、**不引入该依赖**；各功能分支按需引入并写实体 / Mapper（`mapper/` 与 `domain/` 包已预留）。
>
> **数据库（V1.14 起）**：PostgreSQL 17 + pgvector（`pgvector/pgvector:pg17`，5432），表由 Flyway 管理（脚本在 `src/main/resources/db/migration/`）。Boot 4 下除 `flyway-core` / `flyway-database-postgresql` 外，**还必须引 `org.springframework.boot:spring-boot-flyway`**，否则静默不迁移（详见 `medbox-server/README.md`）。

## 零、实施路线图（先读这一节，再认领分支）

原清单按**业务模块**平铺（第一章~第十章），不表达优先级。本节是**实施顺序**维度：**先打通主干闭环，再铺锦上添花**。认领分支时以本节为准。

### 三条实现约定

1. **功能分支必须带集成测试并输出测试报告**（MockMvc 打真实接口链路），交付时把报告摘要给到人 —— 详见 `AGENTS.md` 的 3.1；
2. **判定型分支先出规则表再写代码**（漏服 / 错服 / 提醒 / 时间线 / 库存扣减等），规则表确认后沉淀进 `02` 或 `06`；
3. **合并同类分支**，能在同一分支写完并一起测试的待办合并成一个（下表"合并为"列），PR 描述写明对应第几项，清单里各项都勾选。

### 优先级分层

| 优先级 | 含义 | 何时做 |
|--------|------|--------|
| **P0** | 主干闭环：打通"设备上报 → 判定 → 记录"全链路 | 优先，做完即为可演示 MVP |
| **P1** | 完善：告警、抓拍、环境、监护关系 | P0 完成后 |
| **P2** | 锦上添花：AI 问答 / 知识库 / 统计导出 / 联调工具 | 最后，做不完可砍 |

### 关于 `backend-ai-infra` 的定位

仍在**地基**（第一章第 8 项），但**实施顺序提前到第 2 位**：它只依赖已完成的 `backend-db`，且**需要人在本地起 Ollama 与 RapidOCR 服务**——放到后期做会因人不在场而阻塞，故趁早。其上的 AI 功能分支（`ai-*`）整体归 P2。
