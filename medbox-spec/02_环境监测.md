# 02 · 环境监测（REST 模块分册）

> 本文件是 `02_REST接口设计.md` 的「环境监测」分册。通用约定（统一响应 / 错误码 / 权限默认规则）见根文档 `02_REST接口设计.md` §1。

## 9. 环境监测

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | /env/realtime?deviceId=&sensorId= | 【鉴权】最新温湿光读数（按传感器合并） |
| GET | /env/history?deviceId=&sensorId=&from=&to=&interval= | 【鉴权】历史曲线（小程序图表） |

> **环境阈值按老人统一配置**（不按药品单独设置），走 `PUT /alarm-settings?elderId=` 的 `envThreshold` 字段（见 `02_告警.md` 第 8 章）；判定口径见文档 01 的 5.4。超标告警归环境告警分支，**本分支只落库与查询、不告警、不推 WS**。

### 9.1 实时读数 `GET /env/realtime`
- Query：`deviceId`（必填，药箱主控）；`sensorId`（可选，按传感器查）。
- 权限：`requireDevice(deviceId, READ_ENV)`，越权 / 设备查不到一律 `40301`（与设备类接口同口径，防设备编号枚举）。
- 响应 `R<EnvRealtimeResponse>`：`{ temperature, humidity, lux, sampleTime }`（某传感器无数据则该字段 `null`；`sampleTime` 取温湿度行与光照行中较新者）。温湿度传感器与光照传感器分两条 `env_sample` 入库，本接口合并两者最新非空读数。

### 9.2 历史曲线 `GET /env/history`
- Query：`deviceId`（必填）；`sensorId`（可选）；`from` / `to`（必填，ISO-8601，含端点）；`interval`（可选，分钟，1~1440，分桶 `avg()` 聚合；缺省返回原始有序点）。
- 按 `sensorId` 查询时只筛该传感器 `device_id`，否则按药箱 `gateway_device_id` 筛其下全部传感器。
- 边界校验（不满足 → `40001`）：`from` / `to` 缺省；`from > to`；`interval` 越界（1~1440）；时间跨度 > 30 天。
- 权限：同上 `40301`。
- 响应 `R<EnvHistoryResponse>`：`{ points: [ { sampleTime, temperature, humidity, lux } ] }`。温湿度与光照来自不同传感器、上报时刻不同 —— 原始模式下单行只带一类数值、其余为 `null`；分桶模式下按桶 `avg()` 聚合（`avg` 天然忽略 `null`）。

### 9.3 设备详情附带最新遥测
- `GET /devices/{deviceId}` 的 `DeviceDetailResponse` 新增 `latestTelemetry` 字段（`EnvRealtimeResponse`，无上报时为 `null`），由 `DeviceService.detail` 一并取回。

### 9.4 小程序侧落地（feat/mp-env；env-core 已落地，按契约 + mock 先行）

1. **接口层**：`api/env.js` 的 `getEnvRealtime(deviceId, {sensorId})` / `getEnvHistory(deviceId, {sensorId, from, to, interval})`（GET，Bearer，无 `X-Request-Id`，与 `api/plan.js`、`api/alarm.js` 同口径）。UI 选本地区间（`Date` 区间）后转 ISO-8601 UTC 下发，返回 `sampleTime`（UTC）复用 `utils/datetime.js` 的 `formatDateTime` 本地化展示；前端**不自行换算时区**。
2. **纯函数**：`utils/env.js` 的 `parseEnvRealtime` / `parseEnvHistory`（容错 `{points}` 外壳或裸数组，一处收敛）、`toEnvThresholdView`（**兼容**扁平 `{tempMin,tempMax,humiMin,humiMax,luxMax}`（06 §2.10）与嵌套 `{temp:{min,max},humidity:{min,max},light:{min,max}}`（已落代码 / Mock）两种阈值形状，统一输出嵌套，高亮既兼容当前 Mock 也兼容文档未来扁平形态，且不改动已落地的 `mp-alarm`）、`envMetricStatus`（缺值 / 缺阈值按 `ok`，偏低 `low` / 偏高 `high`）、`computeEnvChartGeometry`（纯几何，可单测）。
3. **页面**：`pages/env/index.vue`（设备详情"环境监测"入口进入）上方实时三卡（温度 ℃ / 湿度 % / 光照 lux，显示当前值 + 阈值区间 + 超标红 / 偏低蓝高亮），下方历史区（区间：近1/7/30天；粒度：原始/10分钟/1小时/1天；传感器：全部/温湿度/光照）+ 自绘 `EnvLineChart` 折线（微信端不支持内联 SVG，用 uni `<canvas type="2d">` 自绘，温/湿/光各一段独立缩放、阈值虚线标示合规区，不引第三方图表库）；空态"暂无环境数据"，错误按 `code` 细分（40301 无权 / 40401 设备不存在 / 40001 参数 / 网络）。
4. **阈值只读**：阈值取自 `api/alarm.js.getAlarmSettings`（已有 GET，带 `elderId`），**仅读取用于高亮**，不新增任何写入口（`WRITE_ALARM_SETTINGS` 仍只在告警设置页）。
5. **权限**：`READ_ENV` 在权限矩阵中老人本人 + 监护人全角色只读，无需新增 `ENTRY_ROLES`、无需 `RoleGate`、不改 `permission.js`；不碰 WS、不新增告警逻辑（ENV 告警归已落的 `env-alarm`）。
6. **mock 先行**：`tools/mock` 补 `env_sample` 种子（给 `BOXA1001` 的温湿度 / 光照子设备生成近 30 天、每小时一条，随昼夜波动）+ `GET /env/realtime`（合并最新非空读数、按 `sensorId` 过滤、无数据返回 `null` 字段、40301/40401/40001）+ `GET /env/history`（from/to/interval 校验→40001；跨度>30天→40001；按 `sensorId` 或 `gateway` 筛；原始 / 分桶 `avg` 返回 points）；仅演示用途，真后端本期已随 `feat/env-core` 落地。
