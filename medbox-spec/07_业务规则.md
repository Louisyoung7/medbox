# 07 · 业务规则（服药判定 / 告警判定 / 提醒生成）

> 本文件集中存放 `06_数据库设计.md` 表结构之外的**判定与生成类业务规则**。字段定义、列语义、建表 DDL 仍在 `06`；本文件只描述"怎么算"。
> 后端实现以本文件 + `06` 列注释为准；判定型分支动手前先出规则表给用户确认（见 `AGENTS.md` 的 3.1）。
> 跨文件引用：`med_record` / `capture` / `plan_reminder` / `alarm` 等表字段见 `06` 对应小节（§2.7 / §2.12 / §2.6.x / §2.9）。

## 1. med_record 服药记录判定规则（服药事件落库）

对应 `06` §2.7 的 `med_record` 表；落库还涉及 `capture`（06 §2.12）与 `plan_reminder`（06 §2.6.x）。字段语义（`record_id` / `cell_no` / `on_time` / `source` 等）见 `06` §2.7。

**1.0 · 上报契约（设备 → 后端，按格取药检测 + 条件式留证）**

设备（摄像头子设备，HMAC 鉴权，按 `parent_device_id` 反查药箱 / 老人）经 `POST /devices/{deviceId}/captures` 上报，字段见 `02b_设备管理.md` §1.1：

- **格号是唯一归属依据**：设备上报 `cellNo`（**1 / 2 / 3**，固件固定对应早 / 中 / 晚），后端据此把事件匹配到计划中该格的槽；**不接收、不记录格内药品与剂量**。
- **取药结论二值化**：设备端侧判定「该格是否被取走」，得出二值结论 `takenResult`（`TAKEN` 已取药 / `UNTAKEN` 未取药）；**不做人脸识别、不报置信度、没有第三态**。
- **条件式留证**：`TAKEN`（正常取药）→ **不上传图片**；`UNTAKEN`（未取药）→ **必须附带抓拍图片**作留证。
- **不再复核**：`UNTAKEN` 记录为**终态**，**不再要求监护人看图复核 / 确认**（见 `02e_服药记录与依从性.md` §1.1）；监护人仍可在设备未上报时**手动补录 / 纠错**，但非强制。
- **无「是否本人」判定**：只能确认「药被取走」，无法确认「是谁取的」。

`planId` 非空才触发落 `med_record`；`TAKEN`/`UNTAKEN` 的 `on_time`、幂等、MISS 兜底见下方规则 1.1~1.6。

**1.1 · 事件准入（不通过 → 丢弃，不落库）**

| 序 | 条件 | 结果 |
| --- | --- | --- |
| ① | 请求体 / 表单非法 | 丢弃 |
| ② | `planId` 或 `cellNo` 为空 | 丢弃 |
| ③ | `cellNo` 不在 `1/2/3` | 丢弃 |
| ④ | 按 HMAC Header 解析的 `deviceId` 查不到 `device`，或 `device.elder_id` 为空 | 丢弃 |
| ⑤ | `plan` 不存在 | 丢弃 |
| ⑥ | `plan.elder_id` ≠ `device.elder_id` | 丢弃（防跨老人伪造） |

补充：`plan.status = DISABLED` **仍落记录**（服药事实已发生）；上报时间取 `capturedAt`（ISO-8601 UTC，缺省取服务器当前 UTC）。

**1.2 · `plan_time` 就近槽匹配（按格）**：取 `capturedAt` 在 `device.timezone`（缺省 `Asia/Shanghai`）下的本地日期 D，生成 **D-1 / D / D+1 三天** × **该计划中 `cellNo` 相同的槽** 的候选，取 `|capturedAt − slot|` 最小者为 `plan_time`（差值相同取较早槽）；**该格无排程**（`slots` 中没有该 `cellNo`）→ `plan_time = NULL`、`on_time = NULL`。

**1.3 · 容忍时长 `resolveToleranceMinutes`（三级，见 §5）**：计划级 `med_plan.miss_alarm_after_min` > 老人级 `alarm_setting.miss_tolerate_min` > 系统默认 **15** 分钟（非空且 >0 才生效，否则下探；老人级无配置行 → 默认）。

**1.4 · `on_time`（单侧窗口，提前恒为 true，只判迟到）**：`plan_time` 为 NULL → NULL；`actual_time ≤ plan_time + 容忍` → true；`>` → false。

**1.5 · 幂等（两层）**：① `capture` 端点按 `planId + cellNo + capturedAt` 60s 时间窗去重（见 02b_设备管理.md §1.1）——重复抓拍只保留第一张；② `uk_med_record_cell_plan_time` 部分唯一索引 `(plan_id, cell_no, plan_time)`——冲突捕获后回滚并不写（同一计划的同一格、同一计划时间只落一条）。

**1.6 · 领域事件**：落库成功后发布服药记录事件，供漏服判定（按 `planId` / `cellNo` / `planTime` 判缺服）消费；**不推 WebSocket、不生成任何告警**（归各自判定逻辑）。事件携带 `recordId/elderId/planId/cellNo/planTime/actualTime/onTime/deviceId/captureId`。

## 2. MISS 判定规则（alarm，定时扫描）

对应 `06` §2.9 的 `alarm` 表（`type = MISS`）。

2.1. **扫描触发**：定时扫描，默认每 60s 一次，不消费服药记录事件做即时判定；扫描窗口 `[now - lookback(默认 1440min), now - tolerance]`，`tolerance` = 三级容忍（见 §5，计划级 > 老人级 > 系统 15min）。
2.2. **候选计划**：只查 `status = 'ENABLED' AND sync_state <> 'SYNC_FAILED'`；`sync_state = PENDING`（未跑同步的测试/演示数据）**仍判**（否则永远看不到告警）；设备离线时（可配置，默认开启）若 MAIN 主控不在线则跳过，避免"上报不了 = 漏服"误判。
2.3. **槽展开**：按设备时区（`device.timezone`，缺省 `Asia/Shanghai`）把 `slots` 展开为 `(cellNo, 计划瞬时)` 候选槽。
2.4. **记录比对**：一次拉取该计划在窗口内的全部 `med_record`，按 `(cell_no, plan_time)` 分组，得到**已有记录的槽集合**（`source` 为 CAMERA / MANUAL 都算）。
2.5. **MISS 判定（一个槽一条告警）**：某槽 `(cellNo, planTime)` 不在集合内 → 判 MISS；生成 **1 条**告警，`message` 只提格号与时间（格式 `08:00 1 号格（早间）未按时取药`，**不提药品名**），`alarm.cell_no` 记该格、`alarm.plan_id` 记计划、`alarm.device_id` 记 MAIN 设备、`type = MISS`、`level = WARN`。该槽有任一记录（无论 `TAKEN` / `UNTAKEN`）→ 不告警；**该格无排程 → 不参与判定**。
2.6. **去重落库**：`dedup_key = MISS:{planId}:{cellNo}:{slotUTC}` 落库，命中 `uk_alarm_dedup_key` 冲突 → 跳过（不二次落库、不二次推 WS）。
2.7. **推送**：落库成功后推 `ALARM` 帧到 `elder:{elderId}`（payload 见 04 第 3 章）；WS 未启用或推送异常 → 静默跳过；单条计划出错不影响其余。
2.8. **边界**：槽时间非法字符串 → 跳过该槽；无 MAIN 设备当离线处理；扫描可整体关闭（逃生开关）。**本逻辑不提供 REST**（列表/已读/处理与阈值配置归告警核心）。

## 3. ENV 判定规则（alarm，事件驱动）

对应 `06` §2.9 的 `alarm` 表（`type = ENV`）。

3.0. **触发**：遥测入库后发布遥测记录事件，由环境告警逻辑消费；无定时全表扫。整体可关闭（逃生开关）。
3.1. **阈值来源（单一来源 = 老人级）**：按 `elder_id` 取 `alarm_setting.env_threshold`（`EnvThreshold`：`tempMin/tempMax/humiMin/humiMax/luxMax`）；判定链：① `alarm_setting` 行不存在 → 不判定；② `env_threshold` 为 `null` → 不判定；③ 某指标上下限为 `null` → 该指标跳过；④ 温/湿为双向（Min/Max）、光照仅上限（`luxMax`）。样本 `elder_id` 为空 → 跳过。
3.2. **越界判定（指标级，每条样本最多 3 条告警）**：温度 `value < tempMin` → "低于下限"、`value > tempMax` → "超出上限"；湿度同口径；光照 `value > luxMax` → "超出上限"。比较用数值比较，**等于边界不算越界**。样本某值为 `null` → 该指标跳过（温湿/光照分两条入库各自判定）。
3.3. **告警落库**：每越界指标 1 条 `Alarm` —— `type=ENV`、`level=WARN`、`device_id` = **传感器自身** `deviceId`（与 `env_sample.device_id` 同源）、`plan_id`/`cell_no` 为 `null`、`message` = "温度 30.5℃ 超出上限 30℃" / "湿度 35% 低于下限 40%" / "光照 800lux 超过上限 600lux"、`read_state=false`、`handle_state=OPEN`。
3.4. **去重与恢复**：`dedup_key = ENV:{elderId}:{sensorId}:{metric}:{bucket}`，`bucket` 由 `sampleTime` 按去重窗口（默认 30min）截断的起始瞬时；命中 `uk_alarm_dedup_key` → 静默跳过。数值回落即停止告警，**不另发恢复通知**；窗口过后再次越界可再告警。
3.5. **推送**：落库成功后推 `ALARM` 帧到 `elder:{elderId}`。WS 未启用或异常 → 静默跳过；单条样本判定失败只记日志不阻断其余上行。
3.6. **边界**：整体关闭时不跑；温湿/光照分两条样本各自判定；无新迁移（复用 `dedup_key` 与序列）。零新增 REST（查询/已读/处理与阈值配置归告警核心）。

## 4. REMINDER 生成规则（plan_reminder，定时扫描）

对应 `06` §2.6.x 的 `plan_reminder` 表（REMINDER 不是告警，只作"每槽只提醒一次"的去重账本）。去重口径 `dedup_key = REMINDER:{planId}:{cellNo}:{slotUTC}`，命中唯一约束冲突即跳过。

**REMINDER 生成规则（定时扫描，默认每 60s）**：窗口 `[now, now + lead-time-minutes]`（默认 10min），只对未来 slot 提醒（已过槽归漏服判定）。

4.1. **候选**：`status='ENABLED' AND sync_state <> 'SYNC_FAILED'`（`PENDING` 演示数据仍提醒）。
4.2. **槽展开**：按 `device.timezone`（缺省 `Asia/Shanghai`）把 `slots` 展开为未来槽（每个槽带 `cellNo`）。
4.3. **两道拦截**：① 已服跳过——该槽已有 `med_record`（`cell_no` + `plan_time` 命中）；② 去重——`plan_reminder` 插入命中 `dedup_key` 唯一约束冲突跳过。
4.4. **组装推送**：推 `REMINDER` 帧 `{planId, planTime, cellNo}` 到 `elder:{elderId}`（**不含药品信息**）。扫描可整体关闭。
4.5. **边界**：默认不要求设备在线；槽时间非法 / 单条出错跳过该槽；无 MAIN 用默认时区；WS 未启用静默跳过。

## 5. 公共口径（漏服定义 / 时区 / 容忍时长）

- **漏服判定口径**：同一 `plan` 的同一 `(cellNo, time)` 槽下，**存在至少一条对应 `med_record`** 才算本次服药完成；**无任何记录即 MISS**（告警只提格号与时间）。MISS 判定算法见 §2。
- **时区口径**：`med_plan.slots[].time` 存设备本地墙钟（如 `"08:00"`），时区取 `device.timezone`（默认 `Asia/Shanghai`）；判定时按该时区换算 UTC 再与 `capturedAt` 比较。跨天 / 计划修改当日生效由定时任务统一处理。所有时间字段一律存 **UTC**。
- **容忍时长三级优先级**：计划级 `med_plan.miss_alarm_after_min` **>** 老人级 `alarm_setting.miss_tolerate_min` **>** 系统默认 **15 分钟**（非空且 >0 才生效，否则下探；老人级无配置行 → 默认）。被 §1.3 与 §2.1 引用。
