# 02 · 服药记录与依从性（REST 模块分册）

> 本文件是 `02_REST接口设计.md` 的「服药记录与依从性」分册。通用约定（统一响应 / 错误码 / 权限默认规则）见根文档 `02_REST接口设计.md` §1。

## 1. 服药记录与依从性

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | /records?elderId=&from=&to= | 【鉴权】服药记录分页（含是否按时、结论 `faceResult`） |
| GET | /records/{recordId} | 【鉴权】记录详情（关联计划与抓拍留证） |
| GET | /adherence?elderId=&period=day\|week\|month | 【鉴权】依从性统计（按时率/漏服） |
| POST | /records/{recordId}/confirm | 【鉴权】监护人手动补录 / 纠错（设备未上报或误判时手工创建 / 纠正记录；不再用于"确认待确认"） |
| GET | /records/export?elderId=&from=&to= | 【鉴权】导出服药报告（监护人用，EXPORT_RECORD 仅 GUARDIAN） |

**接口口径**：

- 列表分页响应按通用约定（`page`/`size`/`total`）；详情由后端 join 计划名 / 药品名返回；列表/详情不暴露文件流，只回传 `captureId`（取文件归抓拍接口）；列表项带 `hasCapture`（缩略图占位，仅 `UNTAKEN` 带图记录为 true）。
- `POST /records/{recordId}/confirm` 单接口双语义：先按 `{recordId}` 查库：① **命中已有记录 → 纠错**：仅覆盖请求体里**非空**的 `actualTime`/`actualDose`/`onTime`/`faceResult`（设备误判 `UNTAKEN` 实则已取时，监护人改写为 `TAKEN`，或反之），`source` 恒置 `MANUAL`；② **记录不存在 → 新建（补录）**：此时路径 `{recordId}` 被**忽略**，由服务端生成新 `mr-` 号并在响应返回，请求体须带 `elderId`/`planId`/`planItemId`/`medicineId`（缺任一带 40001，计划/药品查不到带 40401），`source=MANUAL`，`planTime` 经就近槽重算（无 `planId`/算不出则 NULL）。
- `POST /records/{recordId}/confirm` 仅 `WRITE_RECORD`（GUARDIAN）可调用，老人写 40301、监护 PENDING 40302。

### 1.0 依从性统计 `/adherence` 与导出 `/records/export`（feat/record-report）

**`GET /adherence?elderId=&period=day|week|month`**（权限 `READ_ADHERENCE`，全角色，老人仅本人）：

- 周期 `period` 为**滚动窗口**：day=最近 24h、week=最近 7 天、month=最近 30 天，终点恒为当前时刻（窗口边界取 UTC 瞬时）；`period` 非法（非 day|week|month，含空）→ 40001。
- 统计口径（**分源**，见 `feat/record-report` 规划确认）：
  - `onTimeRate`（按时率）= 周期内 `med_record.on_time=true` 记录数 ÷ 周期内记录总数 `totalDoses`（含 `on_time` 三态，即所有有 `actual_time` 的记录）；
  - `missCount`（漏服数）= 周期内 `alarm.type='MISS'` 条数；**迟到**（`on_time=false` 但有记录）**不计入漏服**，与 11 §2/§5 的 MISS 定义一致；
  - 派生量 `lateCount`（`on_time=false`）、`unjudgedCount`（`on_time=null`，无匹配槽 / 无 `plan_time`）。
- `dailyBreakdown`：按老人 MAIN 设备时区（`DeviceTimezoneResolver`，缺省 `Asia/Shanghai`）做**本地日分桶**趋势（含无数据日，`totalDoses=0` 时 `onTimeRate=0.0`），便于前端画连续折线。
- 响应（`R<AdherenceResponse>`）：`elderId` / `period` / `windowStart`(UTC) / `windowEnd`(UTC) / `totalDoses` / `onTimeCount` / `lateCount` / `unjudgedCount` / `onTimeRate`(0.0~1.0) / `missCount` / `dailyBreakdown[]`（`date` yyyy-MM-dd、`onTimeRate`、`totalDoses`、`onTimeCount`、`missCount`）。

**`GET /records/export?elderId=&from=&to=`**（权限 `EXPORT_RECORD`，**监护人可导出、老人不可**；越权 / PENDING → 40301 / 40302）：

- 响应为 **CSV 文件流**（`Content-Type: text/csv; charset=utf-8`，`Content-Disposition: attachment; filename="medication-records-{elderId}-{from}-{to}.csv"`，带 UTF-8 BOM 便于 Excel），**不走 `R<T>` 包装**。
- `from`/`to` 可选（ISO-8601）：都不传 → 默认**最近 30 天**（`to=now`、`from=now-30d`）；仅传其一 → 另一边界按 30 天窗口推导；格式非法 → 40001。
- CSV 列（表头 + 数据行，值含逗号/引号时按 RFC 4180 转义）：`记录ID,老人ID,计划名,药品名称,计划时间,实际时间,是否按时,结论,来源,剂量,抓拍ID,设备ID`。其中时间列 ISO-8601；`是否按时` 取 `on_time` 的 `true/false`（空为 ""）；`结论`=`faceResult`、`来源`=`source`。

### 1.1 手动补录与纠错（不再有"待确认"）

设备上报已二值化（`faceResult` = `TAKEN` 已取药 / `UNTAKEN` 未取药，详见 `02b_设备管理.md` §1.1 / `11_业务规则.md` §1）：`UNTAKEN` 记录**为终态、不再要求监护人复核 / 确认**，其抓拍原图仅作留证回看、不强制处理。因此本系统**不再有「待确认」派生态**，列表不再提供 `pendingConfirm` 过滤。

- **手动补录**：当设备未上报（离线 / 老人或他人代服等）时，监护人可经 `POST /records/{recordId}/confirm`（记录不存在 → 新建分支）补录一条 `med_record`（`source=MANUAL`）；补录 `TAKEN` 会触发库存扣减（按 `11_业务规则.md` §1 口径，对同一记录仅扣一次），`UNTAKEN` 不扣。
- **纠错**：当设备误判（如实际已取却报 `UNTAKEN`，或反之）时，监护人可经 `POST /records/{recordId}/confirm`（记录存在 → 纠错分支）把 `faceResult` 改写为 `TAKEN`/`UNTAKEN` 纠正；改写为 `TAKEN` 会事后补扣库存。监护人看图留证（`GET /captures/{captureId}/file`）仅为辅助判断、非强制流程。
- **MISS 不受影响**：漏服（`MISS`）仅由"规定时间内无上报"触发（见 `11_业务规则.md` §1 / §2），与是否补录无关；超时未补录的缺报**仍判 MISS**。
