# 08 · 测试体系与 CI

> 本文只写当前测试分层、命令与 CI 口径。契约场景的格式与占位符见 `contracts/README.md`。
> 目标：Mock 与设备模拟器服务于自动化测试和 CI，并在真实多端联调前回答三个问题：
>
> 1. Mock 与真后端是否漂移？
> 2. Flyway 迁移能否在真实 PostgreSQL 上跑通？
> 3. 设备 MQTT 链路是否通？

## 1. 分层

| 层 | 职责 | 位置 | 外部依赖 |
|----|------|------|----------|
| L1 单元 | 纯函数、请求层、编排层 | `medbox-app/src/**/*.spec.js`、`medbox-server/src/test/**/*Test.java` | 无 |
| L2 Mock 测试 | 有状态 CRUD 与流程，供前端开发与快速回归 | `medbox-app/tools/mock` | 无 |
| L3 契约 | 同一场景断言双跑 Mock 与真后端 | `medbox-spec/contracts` + `medbox-app/tools/contract` | 无 |
| L4 真实依赖集成 | Flyway、关键 Mapper 的真实 SQL | `medbox-server/src/test/.../infra` | Docker + PostgreSQL |
| L5 跨进程 E2E | 真后端 jar + seed + 契约 + 设备模拟器 | `.github/workflows/ci-server.yml` 的 `real-e2e` job | PostgreSQL + EMQX |

**为什么保留手写有状态 Mock**：前端需要 PENDING/REVOKED、计划增删等状态流转，无状态契约桩替代不了。契约漂移交给 L3 双跑消除。

## 2. 契约双跑

- 场景在 `medbox-spec/contracts/scenarios/core`，必须同时通过 `--profile mock` 与 `--profile real`。
- 只断言 HTTP 状态、业务码、关键字段类型与存在性；不断言列表条数、记录数、告警数。
- 两端种子不同，用 `baseline.mock.json` / `baseline.real.json` 的占位符隔离：
  - Mock：`u-2001` / `u-1001` / `BOXA1001` / `m-201`
  - 真后端：`u-debug-guardian` / `e-1001` / `BOXA-DEBUG-01` / `m-206`
- 后端未落地的功能（如 AI 洞察）放 `scenarios/mock-only`，`--profile real` 跳过。

命令：

```bash
# 对 Mock（先 npm run mock，默认 8080；CI 用 18099 自起）
node medbox-app/tools/contract/run.mjs \
  --base http://127.0.0.1:8080/medbox/api/v1 --profile mock

# 对真后端（先起后端 + POST /_debug/seed?reset=true）
node medbox-app/tools/contract/run.mjs \
  --base http://127.0.0.1:8080/medbox/api/v1 --profile real
```

## 3. 后端测试任务

`build.gradle.kts` 分两个任务：

| 任务 | 内容 | 依赖 |
|------|------|------|
| `./gradlew test` | 现有 580+ 用例；关闭 Flyway / MQTT / 调度；Mapper 多数打桩，H2 只保证 `@Transactional` 能开连接 | 无 |
| `./gradlew infraTest` | `@Tag("infra")`：Flyway 迁移、关键 Mapper 真实 SQL | Docker（PostgreSQL） |

- `infraTest` 不关 Flyway，容器由 Testcontainers 启动；缺 Docker 时明确失败，不静默跳过。
- 容器镜像用 `pgvector/pgvector:pg17`：V1 有 `CREATE EXTENSION vector`（V18 才 drop），全新库必须先有该扩展；Actions 的 `real-e2e` PostgreSQL service 同此镜像。
- `real-e2e` 启动后端时加 `--medbox.ratelimit.enabled=false`：契约场景逐条登录，同一 IP 60s 内会超过登录限流 10 次（`42901`），测的是契约不是限流。
- 同时把 `--medbox.capture.dir` 指到 `/tmp/medbox-captures`：默认 `/var/medbox/captures` 在 CI 的 runner 用户下不可写，device-sim 的 UNTAKEN 留证图上传会 500。
- 本地可 `-PskipInfra` 跳过。
- MQTT 真实链路不在 `infraTest` 里重复覆盖，交给 L5 的 device-sim smoke。
- 客户端版本检查（`GET /app/version`，见 `02j_客户端版本.md`）的 MockMvc 集成测试并入 `./gradlew test`：不查库、无外部依赖；APK 静态目录与版本号均为配置（`medbox.app.*`），**不改 CI 流程、不产出 APK**。H5 仅本地联调，后端默认不开 CORS。

## 4. CI

### ci-app.yml

```text
npm ci
npm test
npm run test:e2e           # Mock 自身 243 项
npm run test:contract:mock # 契约对 Mock
npm run build:h5
npm run build:app-plus
```

CI 只验证 App 资源编译通过，**不产出 APK**；APK 出包在 HBuilderX 人工完成，真机能力以 APK 验收为准。

### ci-server.yml

| job | 内容 | 外部依赖 |
|-----|------|----------|
| `unit` | `./gradlew test` | 无 |
| `device-sim-unit` | `medbox-server/tools/device-sim` 的 `npm test` | 无 |
| `infra` | `./gradlew infraTest` | Docker + PostgreSQL |
| `real-e2e` | `bootJar` → 起 jar → 等健康检查 → `/_debug/seed?reset=true` → 契约 `--profile real` → device-sim quick smoke | PostgreSQL + EMQX（Actions services） |

`ci-server.yml` 的 `paths` 同时监听：

- `medbox-server/**`
- `medbox-spec/contracts/**`
- `medbox-app/tools/contract/**`

契约变化能触发真实链路回归。

## 5. 一期范围

- 契约核心场景 12 条：登录 / 用户 / 设备 / 药品 / 计划 / 告警设置的主链路与权限分支。
- 后端 infra 测试 4 个：Flyway 迁移、UserMapper、MedicineMapper、PlanMapper。
- MQTT 真实覆盖：device-sim quick smoke（上线、遥测、回执、抓拍）。
- 不重写现有 243 项 Mock E2E。
- 不做 EMQX Testcontainers；不引入 springdoc / Pact / OpenAPI 契约平台。
- 不统一全部种子数据，只维护两份 baseline。

## 6. 三个验收问题

| 问题 | 由谁回答 |
|------|----------|
| Mock 与真后端是否漂移？ | `real-e2e` 里同一份 `core` 场景对真后端全绿；对 Mock 也全绿 |
| 迁移能否在真 PG 跑通？ | `infra` job 的 Flyway 迁移测试 |
| 设备 MQTT 链路是否通？ | `real-e2e` 里 device-sim quick smoke |
