## 1. 设备管理（命令实际经 MQTT 下行）

> `deviceId` 指**药箱主控**，也是 MQTT `clientId`。系统**只登记主控一种设备**，不再有传感器 / 摄像头子设备记录、子设备编号或 `GET /devices/{deviceId}/sensors` 接口；温湿度 / 光照读数由主控直接上报并挂在该 `deviceId` 下（见文档 03），摄像头抓拍也用同一个主控 `deviceId` 经 HTTP 上报（见 §1.1）。

### 1.0 设备注册与查询

**谁可以注册**：`POST /devices/register` 是**监护人代老人**登记设备 —— 走 `require(elderId, WRITE_DEVICE)`，**只 GUARDIAN 监护人具备该权限**。老人本人（`SELF`）一律 40301。**前置条件：监护人须与目标老人已存在 ACTIVE 监护关系**；申请状态仍为 PENDING 时返回 40302，无关系 / REVOKED 返回 40301（老人端确认后才可登记）。设备端**不做无 Token 自注册**，仍走 JWT。`deviceId` **由设备固件生成并固化**（生成方式属设备实现，后端不关心；后端只校验 4~64 位 `[A-Za-z0-9_-]` 与全局唯一），监护人扫码 / 手填该 ID 完成登记。**本期注册即生效**，不做准入审核；请求体不再有 `sensors` 数组；`onlineState` 恒为 `OFFLINE` —— 真正的在线要等设备连上 EMQX。

**错误码口径**（沿用 02_REST接口设计.md §1.2 / §1.3，不新增码值）：

| 场景 | 结果 |
|------|------|
| 老人本人注册 | 40301（`WRITE_DEVICE` 仅 GUARDIAN） |
| 监护关系 PENDING | 40302 |
| **设备编号已登记** | **40901** —— `device_id` 唯一，不静默覆盖、不改绑 |
| 编号格式非法 / 时区非法 / `page` 或 `size` < 1 | 40001 |
| **查询他人设备，或设备不存在** | **一律 40301**（不返回 40401，防设备编号枚举） |

**事件流水 `GET /devices/{deviceId}/events`**：分页返回，`page` 从 1 起，不传即用默认 20；`size` 超过上限静默取上限；`page`/`size` 小于 1 报 40001。按 `created_at` **倒序**（最新在前）。数据源是 `device_event` 表，写入 `REGISTERED` / `ONLINE` / `OFFLINE` / `FAULT` / `COMMAND` 五类：前三类由设备登记与在线状态跃变生成，`FAULT` 由设备异常上报生成，`COMMAND` 由命令下发与回执终态生成。

**在线状态只写"跃变"**：只有状态真的变了才落流水（同时推 `DEVICE_STATUS` 帧，见文档 04）。

**两处刻意留空（接口结构不动，待后续补）**：

- `GET /devices/{deviceId}` 的**最新遥测**：读数在 `env_sample` 表，届时在响应里加字段即可；
- `GET /devices/{deviceId}/status` 的**仓门状态**：设备侧尚未上报、设备表也无该列，等上报后再补。

#### 1.0.1 命令下发

**请求体口径**：`cmd`（必填，`REBOOT` / `CALIBRATE`）+ `params`（可选 Map，如 `REBOOT` 的 `durationSec`）；声光 `BUZZ` / 开格 `UNLOCK` 由设备本地或客户端本地触发，后端不下发。**请求体不收 `operator`** —— 操作人由服务端取鉴权用户落 `device_command.operator_id` 留痕（不信客户端自报身份）。

**判定表（顺序即优先级）**：

| 场景 | 结果 |
|------|------|
| 设备不存在 / 越权 / 老人本人 | **40301**（`WRITE_DEVICE` 仅 GUARDIAN；不区分不存在与无权限，防编号枚举） |
| 监护关系 PENDING | 40302 |
| `cmd` 不在白名单 | 40001 |
| **设备离线（`online_state != ONLINE`）** | **40901** —— 提示"设备离线，无法下发" |
| MQTT 未启用 | 50000（**不落库**：命令是用户主动的同步操作，悬挂 PENDING 没意义） |
| 受理成功 | 200，`{commandId, state:"PENDING"}`，异步等回执 |

**终态流转**：受理落 `device_command`（PENDING）→ 转 MQTT `down/command`（QoS1、信封带 `msgId` + `needAck:true`）→ 设备回执 `up/ack` 或 5s 超时重发 3 次仍无回执 → 行翻 `SUCCESS` / `FAILED` 终态（更新条件带 `state='PENDING'`，迟到/重复回执幂等）。**发布当场抛异常**→ 行置 FAILED + 50000。

**COMMAND 事件契约**：每次下发写一条 PENDING 事件、翻终态再写一条，`detail` 为 JSON `{"commandId","cmd","state"[,"reason"]}`（见 06 的 2.16 / 2.17）。**不生成告警、无命令查询接口、无 WS 帧** —— 前端刷 `GET /devices/{id}/events` 观察终态。

### 1.1 设备抓拍与服药上报（摄像头经 HTTP 直连后端；取药结论 + 仅未取药时附图）

设备端侧判定**对应格位的药格是否被取走**，并**经本接口 HTTP multipart 上报「格号 + 是否拿药」结论（`cellNo` + `takenResult`，后者值 `TAKEN` 已取药 / `UNTAKEN` 未取药）**；**仅在 `UNTAKEN`（未拿药）时才附带抓拍图片作留证**，正常 `TAKEN` 不上传图片（摄像头支持 HTTP；单片机与摄像头内部如何协同是设备实现细节、前后端不约束，见文档 03 第 4 章 / 文档 01 §2.3）。后端**不运行图像识别**，仅据 `takenResult` 统计已取药 / 未取药；超时（规定时间内）无上报仍由后端兜底判漏服（`MISS`）。

> **后端不跑识别**：设备端侧给出二值结论随上报发出：正常 `TAKEN` 仅发结论、不传图（轻量）；`UNTAKEN` 必带抓拍图片作留证（供回看，但**不再要求监护人复核**，见 `02e_服药记录与依从性.md` §1.1）。**`planId` 非空时**，本接口除落 `capture` 外，还按 `07_业务规则.md` §1 判定规则落一条 `med_record`（含 `cell_no` / `taken_result`），即一次上报同时产生留证图（仅 UNTAKEN）与服药业务记录（大致 1:1）；`planId` 为空（如 `MANUAL` 留证）只落 `capture`、不产生 `med_record`。**格号是设备事件与计划槽的唯一对应依据**：后端不接收药品、剂量等格内信息。

**约定**：

- **`reason` 取值**：`NORMAL` 正常服药上报 / `MANUAL` 监护人主动请求留证（仅留证、不产生 `med_record`）。列表接口可按 `reason` 过滤。
- **去重规则（实现确定）**：同一服药事件**只保留 1 张**。`planId` 非空时按 **`planId + cellNo`** 分组，再按 `|capturedAt − 已有 capturedAt| ≤ 60s` 判定重复，命中只保留第一张；`planId` 为空不去重。
- **不再有「待确认」**：设备只给二值结论 `TAKEN`/`UNTAKEN`；`UNTAKEN` 带抓拍图作留证，**但不再要求监护人复核 / 确认**（见 `02e_服药记录与依从性.md` §1.1 手动补录与纠错）。
- **必带字段**：`planId` 非空（服药事件上报）时，`cellNo`（1/2/3）与 `takenResult`（`TAKEN`/`UNTAKEN`）为核心**必带**字段；`cellNo` 缺失 / 越界 → 40001；`takenResult` 缺失仍落库、`taken_result` 兜底置 `UNTAKEN`。仅 `reason=MANUAL` 的监护人主动留证可空。后端对非关键缺失字段**容错不报错**（设备侧健壮性优先），不因此丢弃上报。
- **上传侧校验设备身份，不走用户 JWT**：见 1.1.1。MQTT 通道本期是匿名的，与此处的 HTTP 上传身份校验相互独立。
- **下载侧鉴权**：必须是**老人本人**或其 **ACTIVE 监护人**，其余角色（非 GUARDIAN / 非本人）一律 40301 —— 比 1.3 的默认规则更严格。
- **为什么用 query 传 token**：客户端 `<image src>` 无法携带自定义 Header（H5 / APP 一致），故用后端签发的**短期 `fileToken`**（5 分钟有效）拼接在 URL 上；**不要直接把长期 JWT 放 URL**（会落进日志与浏览器历史）。
- **过期清理（分有图 / 无图）**：仅**带图记录（`UNTAKEN`）**走"已读 / 未读"公式 `expire_at = MIN(captured_at + 30 天, viewed_at + 7 天)`（未读最长 30 天；首次查看后再保留 7 天，查看只提前不延长）；**无图记录（`TAKEN`）**无图片可看，`expire_at = captured_at + 30 天`（固定保留期，天数可配）。首次调用 `/captures/{id}/file` 读取图片流时后端自动写入 `viewed_at` 并重算 `expire_at`。后端每日定时任务删除到期文件与记录，监护人可手动提前删除（由 `feat/capture-cleanup` 实现；可通过 `medbox.capture.cleanup.enabled` / `medbox.capture.cleanup.cron` / `medbox.capture.cleanup.batch-size` 配置总开关、扫描时刻与每轮批量上限，孤儿遗留文件 best-effort 同步清理）。
- **存储**：图片存后端主机本地目录，不落库、不暴露真实路径；落盘路径 `{dir}/{YYYY-MM-DD}/{captureId}.{ext}`，`file_path` 入库但**绝不出现在任何响应里**。`{ext}` 由上传 `Content-Type` 推导（仅 `jpg`/`png`/`webp`，其余兜底 `jpg`），**不使用原始文件名**（防路径穿越）。

##### 1.1.1 上传侧身份校验（不走 JWT、无签名）

`POST /devices/{deviceId}/captures` 从 `AuthInterceptor` 排除，只校验设备身份、不走用户 JWT；**请求体 / Header 不再携带任何摄像头子设备 ID**。路径中的 `deviceId` 就是药箱主控 ID，与 MQTT `clientId` 一致。

后端校验：按路径 `deviceId` 查库确认设备已登记并直接取其 `elder_id`（未登记 → 40301），只允写入该设备所属老人。**不再有** `X-Device-Id`、父子设备反查与“设备编号不一致”错误。

> **入口唯一**：服药事件**只**经本 HTTP 端点上报，不经 MQTT。判定核心 `DispenseConsumeService` 按 `cellNo` 做就近槽匹配，直接按主控 `deviceId` 归属老人落 `med_record`（`onTime` / 三级容忍口径见 `07_业务规则.md`）。

##### 1.1.2 错误码与边界（不新增码值，沿用 02_REST接口设计.md §1.2 / §1.3）

| 端点 | 场景 | code | HTTP |
|------|------|------|------|
| ① 上传 | `UNTAKEN` 未带 `file`（缺留证）/ `reason` 非法 / 缺参 | 40001 | 400 |
| ① 上传 | 设备未注册（解析不出老人） | 40301 | 403 |
| ① 上传 | 文件落盘 IO 失败 | 50000 | 500 |
| ②/③ 列表/详情 | 无关系 / 老人看他人 | 40301 | 403 |
| ②/③ 列表/详情 | 监护关系 PENDING | 40302 | 403 |
| ③ 详情 | `captureId` 不存在 | 40401 | 404 |
| ⑤ 文件流 | `token` 缺失 / 格式非法 / `token.captureId ≠ 路径` | 40001 | 400 |
| ⑤ 文件流 | `token` 签名无效 / 已过期 | 40101 | 401 |
| ⑤ 文件流 | `captureId` 不存在 / 磁盘文件已被清理 | 40401 | 404 |
| ⑤ 文件流 | 监护关系不符（二次复核，令牌泄漏也兜底） | 40301 / 40302 | 403 |
| ⑥ 删除 | `captureId` 不存在 / 已被清理 | 40401 | 404 |
| ⑥ 删除 | 老人本人调用 | 40301 | 403 |
| ⑥ 删除 | GUARDIAN 但监护关系 PENDING | 40302 | 403 |

> **去重命中**：返回既有记录的 `captureId`/`expireAt`，本次文件流丢弃不落盘；`planId` 非空且判定核心成功时额外回带 `recordId`，否则为 `null`；`TAKEN` 无图记录 `expireAt` 按固定期、`fileToken` 为 `null`。**读取图片流不走统一响应体包裹**（直接返回二进制，`Cache-Control: no-store`），仅带图记录（`UNTAKEN`）有图可取，无图记录（`TAKEN`）返回 40401。
