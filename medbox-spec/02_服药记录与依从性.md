# 02 · 服药记录与依从性（REST 模块分册）

> 本文件是 `02_REST接口设计.md` 的「服药记录与依从性」分册。通用约定（统一响应 / 错误码 / 权限默认规则）见根文档 `02_REST接口设计.md` §1。

## 7. 服药记录与依从性

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | /records?elderId=&from=&to=&pendingConfirm= | 【鉴权】服药记录分页（含是否按时、是否待确认 `pendingConfirm`；可按 `pendingConfirm=true` 过滤待确认） |
| GET | /records/{recordId} | 【鉴权】记录详情（关联计划与抓拍留证） |
| GET | /adherence?elderId=&period=day\|week\|month | 【鉴权】依从性统计（按时率/漏服） |
| POST | /records/{recordId}/confirm | 【鉴权】监护人补录/确认（设备异常时手工校准；亦用于确认待确认记录） |
| GET | /records/export?elderId=&from=&to= | 【鉴权】导出服药报告（护理/医生用） |

**接口口径**：

- 列表分页响应按通用约定（`page`/`size`/`total`）；详情由后端 join 计划名 / 药品名返回；列表/详情不暴露文件流，只回传 `captureId`（取文件归抓拍接口）；列表项带 `hasCapture`（缩略图占位）与派生 `pendingConfirm`（待确认标志）。
- `POST /records/{recordId}/confirm` 单接口双语义：先按 `{recordId}` 查库：① **命中已有记录 → 校准**：仅覆盖请求体里**非空**的 `actualTime`/`actualDose`/`onTime`/`faceResult`（待确认记录经人工看图后改写 `faceResult` 为 `TAKEN`/`ABSENT`，`confidence` 可置空），`source` 恒置 `MANUAL`；② **记录不存在 → 新建（补录）**：此时路径 `{recordId}` 被**忽略**，由服务端生成新 `mr-` 号并在响应返回，请求体须带 `elderId`/`planId`/`planItemId`/`medicineId`（缺任一带 40001，计划/药品查不到带 40401），`source=MANUAL`，`planTime` 经就近槽重算（无 `planId`/算不出则 NULL）。
- `POST /records/{recordId}/confirm` 仅 `WRITE_RECORD`（GUARDIAN）可调用，老人写 40301、监护 PENDING 40302。

### 7.0 依从性统计 `/adherence` 与导出 `/records/export`（feat/record-report）

**`GET /adherence?elderId=&period=day|week|month`**（权限 `READ_ADHERENCE`，全角色，老人仅本人）：

- 周期 `period` 为**滚动窗口**：day=最近 24h、week=最近 7 天、month=最近 30 天，终点恒为当前时刻（窗口边界取 UTC 瞬时）；`period` 非法（非 day|week|month，含空）→ 40001。
- 统计口径（**分源**，见 `feat/record-report` 规划确认）：
  - `onTimeRate`（按时率）= 周期内 `med_record.on_time=true` 记录数 ÷ 周期内记录总数 `totalDoses`（含 `on_time` 三态，即所有有 `actual_time` 的记录）；
  - `missCount`（漏服数）= 周期内 `alarm.type='MISS'` 条数；**迟到**（`on_time=false` 但有记录）**不计入漏服**，与 11 §2/§5 的 MISS 定义一致；
  - 派生量 `lateCount`（`on_time=false`）、`unjudgedCount`（`on_time=null`，UNCERTAIN / 无匹配槽）。
- `dailyBreakdown`：按老人 MAIN 设备时区（`DeviceTimezoneResolver`，缺省 `Asia/Shanghai`）做**本地日分桶**趋势（含无数据日，`totalDoses=0` 时 `onTimeRate=0.0`），便于前端画连续折线。
- 响应（`R<AdherenceResponse>`）：`elderId` / `period` / `windowStart`(UTC) / `windowEnd`(UTC) / `totalDoses` / `onTimeCount` / `lateCount` / `unjudgedCount` / `onTimeRate`(0.0~1.0) / `missCount` / `dailyBreakdown[]`（`date` yyyy-MM-dd、`onTimeRate`、`totalDoses`、`onTimeCount`、`missCount`）。

**`GET /records/export?elderId=&from=&to=`**（权限 `EXPORT_RECORD`，**监护人可导出、老人不可**；越权 / PENDING → 40301 / 40302）：

- 响应为 **CSV 文件流**（`Content-Type: text/csv; charset=utf-8`，`Content-Disposition: attachment; filename="medication-records-{elderId}-{from}-{to}.csv"`，带 UTF-8 BOM 便于 Excel），**不走 `R<T>` 包装**。
- `from`/`to` 可选（ISO-8601）：都不传 → 默认**最近 30 天**（`to=now`、`from=now-30d`）；仅传其一 → 另一边界按 30 天窗口推导；格式非法 → 40001。
- CSV 列（表头 + 数据行，值含逗号/引号时按 RFC 4180 转义）：`记录ID,老人ID,计划名,药品名称,计划时间,实际时间,是否按时,结论,来源,剂量,抓拍ID,设备ID`。其中时间列 ISO-8601；`是否按时` 取 `on_time` 的 `true/false`（空为 ""）；`结论`=`faceResult`、`来源`=`source`。

### 7.1 待确认与人工确认闭环（置信度阈值触发）

摄像头上报的 `confidence` 低于阈值（可配，默认 0.6）或 `faceResult = UNCERTAIN` 时，落库的 `med_record` 即处于**待确认**态。待确认是 `med_record` 的**派生状态**（不单独存字段）：`pendingConfirm = (confidence IS NULL OR confidence < 阈值) OR faceResult = 'UNCERTAIN'`。

- **暴露**：`GET /records` 列表项带派生 `pendingConfirm` 布尔与 `captureId`；监护人按 `pendingConfirm=true` 过滤即可看到"待我裁定"的服药记录（见 `02_设备管理.md` §4.1 抓拍列表只按 `reason` 过滤、不含待确认，故待确认统一在记录列表呈现）。
- **确认动作**：监护人先调 `GET /captures/{captureId}/file` 看原图留证，再调 `POST /records/{recordId}/confirm` 把 `faceResult` 改写为 `TAKEN`（确认已服）/ `ABSENT`（确认未服），`source` 恒置 `MANUAL`、`confidence` 可置空；改写后 `pendingConfirm` 自动解除。确认 `TAKEN` 会触发库存扣减（按 `11_业务规则.md` §1.5 口径，对同一记录仅扣一次）；确认 `ABSENT` 不扣减。
- **不自动解除**：后端**不据原图做识别**，故待确认只能由人工看图确认，不会因时间流逝自动变成已服/未服；超时未确认的待确认**不转 MISS**（MISS 仅由"规定时间内无图片上报"触发，见 11 §1 / 文档 10 §2.1）。
