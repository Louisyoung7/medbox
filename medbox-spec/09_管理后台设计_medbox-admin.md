## 一、定位与本期范围

`medbox-admin/` 原在 00 索引里是「本期占位，暂不实现」。现决定**提前只做一件开发/测试侧的刚需**：

> **测试数据清理**：双人在本地独立开发，常注册一堆测试账号（监护人 / 老人），用完容易忘删；用 DataGrip 手工删又怕漏表、触发外键 / 孤儿行。**需要一个带护栏的界面，安全地列出并清除测试用户及其孤儿数据。**

**本期只交付这个工具**，明确边界：

- 它是 **dev / QA 专用工具**，**不进入普通产品导航**，UI 明确标注「测试数据清理 · 开发/测试专用」。
- 建议在**开发 / 测试库**使用，**不接生产库**（生产库不该有 `test*` 账号，且硬删会丢健康留痕）。
- 硬删有**多重护栏**，ACTIVE 真账号一律拒绝（见第二章、第四章；后端护栏见 `02` 第 10 章）。

**不在本期**：真实产品后台（用户管理、设备管理、统计看板等）。后续若扩展产品后台，再补 07 / 08 清单。

## 二、角色与登录

- **ADMIN 角色与门禁**：`UserRole` 增加 `ADMIN` + 种子管理员账号（`V10__admin_seed.sql`，`username=admin`、`password=public`） + 独立角色守卫，覆盖所有 `/admin/**`（非 ADMIN 一律 `40301`）。详见 `02` 第 10 章与 `06` 的 2.1。
- **登录**：复用现有 `POST /auth/login`（账号可为手机号或用户名），admin 种子账号登录后拿到普通 JWT，管理接口额外要求 `role == ADMIN`（见 `02` 第 3 章 / 第 10 章）。

## 四、安全护栏（前端侧）

后端侧护栏（角色门禁、`ACTIVE` 拒绝 `40902`）见 `02` 第 10 章。前端侧额外护栏：

1. **默认视图收敛**：前端列表默认只展示「`status=DELETED` 或 `username LIKE 'test%'` 或 `phone LIKE '1380000%'`」的账号；看 ACTIVE 需显式切换筛选项，降低误删面。
2. **二次确认 + 输入校验**：点「清理」弹确认框，**要求手输目标 `userId`** 才放行，防误点。
3. **明确标识**：页面顶部固定标注「测试数据清理 · 开发/测试专用，勿接生产库」。
4. **审计（可选）**：清理操作写一条审计日志（操作人 admin、目标 userId、时间），便于回溯。

## 五、前端方案

### 5.1 技术栈（已确认：默认 Vue3 + Element Plus）

- **Vue 3 + Vite + Element Plus**（与 `medbox-miniapp/` 同为 Vue3 系，降低上下文切换；Element Plus 含表格 / 表单 / 弹窗 / 二次确认组件，最贴合后台）—— 已采纳为默认。
- 备选 React + Ant Design 仍可行（用户对两者无偏好），但本期按计划落地，不另起 React 工程。

### 5.2 页面

- `/login`：管理员登录（手机号/用户名 + 密码），成功后存 JWT 与 `role` 到 `localStorage`；路由守卫拦截未登录或非 ADMIN。
- `/test-data`（清理主页）：
  - 筛选条：`status` 下拉（默认「测试/已注销」）、`keyword` 输入框、`role` 下拉、「查询」「重置」按钮；
  - 用户表格：`userId` / `role` / `name` / `phone`(可为空) / `username`(可为空) / `status` / `createdAt` + 每行「清理」按钮（ACTIVE 行禁用并提示「活跃账号不可清理」）；
  - 批量入口：「清理全部已注销测试用户」按钮（按当前筛选批量调用 `DELETE /admin/users/{userId}`）；
  - 二次确认：弹框要求手输 `userId` + 明确后果提示。

### 5.3 接口调用

- `axios` 封装：`baseURL` 指向后端 `http(s)://<host>:8080/medbox/api/v1`，统一附 `Authorization: Bearer <token>`；复用 `02` 的 `R<T>` 响应与错误码解析（如 `40902` 弹「活跃账号不可清理」提示）。
- host/端口走 `.env`（参考 `medbox-miniapp/` 的 `src/config` 兜底逻辑），默认 `127.0.0.1:8080`。

## 七、已确认事项（原开放问题已闭合）

以下四点用户已拍板，作为后续实现约束：

1. **前端栈**：默认 **Vue 3 + Vite + Element Plus**（与小程序同系）；用户明确表示 React + Ant Design 亦可、但无偏好，故按默认落地，不另起 React 工程。

4. **种子 admin 凭证**：`username=admin`、`password=public`、`status=ACTIVE`、`role=ADMIN`；**不做首次强制改密**（后端落地见 `06` 的 V10）。
