## 1. 告警（列表/处理，实时推送走 WebSocket）

**告警类型枚举**

| type | 触发来源 | 说明 |
|------|----------|------|
| MISS | 后端判定 | 计划时间+容忍时长内**该格**未收到服药上报（按槽判定；**告警只提格号与时间，不提药品名**；后端定时判定生成并经 WS 推送） |
| ENV | 设备上报 | 温度/湿度/光照超出**该老人统一配置的 `envThreshold`**（不按药品细分，见文档 01 的 5.4） |
| DEVICE_OFFLINE | 后端判定 | 心跳超时，设备离线超阈值（**仅主控**，传感器子设备离线不生成告警） |
| DEVICE_FAULT | 设备上报 | 设备侧异常（`up/event/error`）：门超时 / 识别失败 / 硬件故障 |

> **MISS 告警归属**：由后端**生成** MISS 告警（落 `alarm` 表 + 经 WebSocket 推 `ALARM` 帧）；查询 / 已读 / 处理与阈值配置归告警核心分支。生成分支本身不新增任何 REST。

> **告警阈值配置权限**：列表 / 未读 / 已读 / 设置查询用 `READ_ALARM`（老人本人 + GUARDIAN 可读）；处理/确认用 `HANDLE_ALARM`（仅 GUARDIAN）；配置阈值用 `WRITE_ALARM_SETTINGS`（**仅 GUARDIAN** 监护人代老人配置，非 GUARDIAN 写返回 40301）。`alarm_setting` 每老人一行（`elder_id` UNIQUE），无则插入、有则更新；请求字段可选、仅提供项覆盖原值。

**权限与接口口径**：

- `type`/`readState` 传 `'ALL'` 视为不过滤；写操作自动注入 `X-Request-Id`。
- 监护人选老人（elderId）：监护人侧可见老人由 `GET /devices` 推导（每台 MAIN 主控的 `elderId` 即一位老人）；ELDER 角色直接用自身 `userId`；WS 订阅主题同样由该推导结果传入（老人端省略）。
- 服务端对每个接口均强校验对应权限位（见上）。
- 未读角标与实时告警：`GET /alarms/unread-count` 驱动角标；WS 收到 `ALARM` 帧 → 全局弹窗 + 未读 +1；`RESYNC` 触发列表页 REST 全量拉取；`REMINDER` 帧 → 按格提醒（带 `cellNo`，**非告警、不进列表**）。
- 归一化与容错：列表响应兼容 `{list,total}` / `{records}` / `{items}` / 裸数组；配置缺字段兜底默认值（提前期 10 / 漏服容忍 15 / 温湿光上下限）。
