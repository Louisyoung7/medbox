# 速览（QUICKSTART）— 只需要看这一页

> 本页回答三件事：项目是什么、怎么开工、想查东西去哪。其余文档当字典用，不用通读。

## 一、项目是什么（10 行版）

家用智能药品箱，纯局域网通信：

- **设备**（药箱主控 + 传感器 + 摄像头）经 **MQTT(EMQX)** 上报
- **Java 后端**（`medbox-server/`，Spring Boot 4 + Java 21）落库并判定
- **uni-app 小程序**（`medbox-miniapp/`）通过 **HTTP REST + WebSocket** 交互
- **AI 问答**走大模型（后端不托管，监护人代配 Key）
- `medbox-admin/` 本期只做测试数据清理工具
- 本目录 `medbox-spec/` 是唯一权威文档集

## 二、怎么开工（三步）

1. **同步**：`git switch main && git pull && git switch -`
2. **开工**：从 main 切特性分支（后端 `feat/backend-xxx` / 小程序 `feat/mp-xxx` / Web `feat/admin-xxx` / 文档 `docs/xxx`），一切改动都在特性分支上，绝不碰 main
3. **收尾**：修正受影响的 spec 文档 → 与代码同一 PR 提交

> 首轮开发的分支清单已归档（`archive/07` / `08` / `09`），查历史分支与依赖关系去归档；后续新增分支不再建清单文件，实现口径直接沉淀到对应 spec 文档。

细节规则（集成测试、rebase、Flyway 编号等）在仓库根 `AGENTS.md`，AI 自动加载，**人不用看**。

## 三、查东西去哪

| 我想查… | 去这 |
|---------|------|
| 某接口的字段 / 错误码 | `openapi/<模块>.yaml`（**唯一契约源**） |
| 某业务怎么判定（漏服、告警、提醒） | `11_业务规则.md`，或该模块分册 `02a~02h` 的规则表 |
| 表结构 / DDL | `06_数据库设计.md` |
| 设备 MQTT 上报格式 | `03_设备接入协议_MQTT.md` |
| WebSocket 推送格式 | `04_实时推送协议_WebSocket.md` |
| AI 大模型怎么接 | `05_AI大模型与RAG方案.md` |
| 全局口径（时区 / 权限 / 部署） | `01_系统架构与产品定义.md` |
| 项目进展到哪了 | `git log --oneline` 与历史分支清单（归档 `archive/07` / `08` / `09`） |

| 历史变更 | `git log -- medbox-spec/`（变更归档在 `archive/CHANGELOG.md`，已冻结） |

## 四、哪些人看，哪些交给 AI

**推荐人自己看的**（薄、且需要你做判断）：

| 文档 | 什么时候看 |
|------|-----------|
| 本页 `QUICKSTART.md` | 唯一的入门必读 |
| `01` §2（产品定义）与 §4（IP/端口规划） | 想了解产品形态、部署联调时 |
| `02a~02h` 各分册的规则表 + `11` 业务规则 | **讨论口径、对需求时**——这些是「为什么这么算」，AI 改代码前也需要你确认 |
| 归档 `archive/07/08/09` | 查首轮某个分支当时怎么做的 |

**推荐交给 AI 看的**（厚、且是机械契约，AI 自动检索即可，人不用背）：

| 文档 | 说明 |
|------|------|
| 根目录 `AGENTS.md` | AI 自动加载，工作流/铁律全在这里，人不用看 |
| `openapi/*.yaml` | 唯一契约源，AI 实现接口时以它为准 |
| `02` 根册 + `02a~02h` 的字段/端点细节 | AI 按需查，人只在评审 yaml diff 时扫一眼 |
| `03` / `04` / `05` / `06` | 协议与表结构字典，AI 写代码前自动读对应章节 |

一句话：**「怎么算、为什么」人来拍板（11 + 分册规则表），「是什么、长什么样」AI 去查（yaml + 03/04/06）**。

## 五、给 AI 助手的话

动手前：读仓库根 `AGENTS.md`（自动加载）→ 本页 → 对应模块文档。契约以 yaml 为准，发现歧义先问用户，不要擅自偏离文档。
