## 1. 药品与库存管理

> **后端不建模格子（带锁分层药箱）**：药箱为分层结构（上层带锁分格每日用药区、下层仓储区），格子是药箱本地物理概念、`cell_id` 不入库；库存按"药箱 + 药品"管理（表 `medicine_stock`，见文档 06 的 2.5）；传感器则按**子设备**细分（`device.device_type` + `parent_device_id`），见文档 06 的 2.3。

**接口口径**：

- **新建与更新同走 `POST /medicines`**：更新时请求体带 `medicineId`，创建不带（由后端生成）；`ownerElderId` **不传即公共字典**，传某老人 `userId` 即其私有药品。可见范围（公共 + 我监护老人的私有）由后端按 `visibleElderIds()` **行级过滤**。
- **分页响应形状**：`GET /medicines` 按通用约定收 `page` / `size`、返回 `total`；列表数组字段名以最终实现为准。
- **删除 40901**：药品被任一药箱库存引用（`medicine_stock.medicine_id` 存在记录）时拒绝删除。
- **写权限**：药品写与库存四条均属 `WRITE_MEDICINE`（02_REST接口设计.md §1.3 矩阵，仅 GUARDIAN）；服务端强校验。

**库存四条 · 判定与口径**：

1. **响应形状**：`GET /devices/{deviceId}/stocks` 的列表行级字段即 06 的 2.5（`stockId` / `medicineId` / `quantity` / `productionDate` / `expiryDate` / `updatedAt`），**不内嵌药品摘要** —— 名称 / 规格 / 单位由客户端拉药品字典按 `medicineId` join。
2. **PUT 覆盖写 vs POST /in 增量**：PUT 录入/更新与 POST `/in` 补药入库均为 `{ quantity, productionDate?, expiryDate? }`；**PUT 的 `quantity` 为绝对值（覆盖写）**，**POST `/in` 的 `quantity` 为增量**；两个日期均为 `YYYY-MM-DD`（DATE 列，选填，不传即不更新该列）。
3. **设备维度错误码**：沿用 `02b_设备管理.md` 第 1 章口径 —— 查询 / 操作他人设备与设备不存在**一律 40301**（不返回 40401，防设备编号枚举）；数量非法等参数错误 40001。
4. **日期无时区换算**：`productionDate` / `expiryDate` 是 DATE（无时刻），直接收发 `YYYY-MM-DD`，**不走 02 §1 通用约定的 UTC 口径**（该口径的例外只有服药计划 `times` 与 DATE 列）。
